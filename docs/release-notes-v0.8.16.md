# v0.8.16 发布说明

**发布时间**：2026-11-23 · **版本** `0.8.16+2016` · 三个 ABI 包（arm64-v8a / armeabi-v7a / x86_64）

这一版只做一件事：**让自动记账在 App 不在前台时，也尽量别漏记账**。

---

## 一、以前为什么会漏

支付通知来的时候，App 可能不在后台。系统的「通知使用权」虽然开着，但国产 ROM 有两条常见行为：

1. 把后台进程回收掉；
2. 权限开关还显示「已开启」，实际却没把监听服务绑上。

两种情况都会让通知**根本进不了记账队列**，你之后再打开 App 自然补不回来。
（系统的历史通知接口不对普通 App 开放，所以「事后回捞」这条路不存在。）

## 二、这版加了什么

`我的 → 自动记账` 页最上面多了「**后台常驻**」开关（**默认关闭**，由你自己决定要不要开）：

- **常驻服务**：打开后状态栏会出现一条「自动记账待命中」的低优先级提示，
  系统更难回收 App，通知更容易被接住；
- **每 10 分钟自愈**：如果发现监听被系统断开了，会自动请求重新绑定，并顺带续期补抓；
- **两行系统设置引导**：
  - 「省电优化」—— 显示是否已忽略，点一下直接跳到系统设置；
  - 「自启动」—— 跳到系统的自启动管理（小米机有专属页，其它品牌去应用详情里找）。

App 每次冷启动 / 回到前台都会自动确认常驻服务还在跑，不会重复弹通知。

## 三、要不要开？怎么判断

- 你经常「付完款过一阵才打开 App」→ **建议开**，代价只是状态栏多一条不打扰的提示；
- 你习惯付完就打开 App → 可以不开，原有逻辑一样能记上；
- 开完记得顺手把「省电优化」设为「无限制」—— MIUI 的省电策略仍是最大的变数。

## 四、诚实说明

常驻服务能显著降低漏记概率，但**不能承诺 100%**：如果系统在支付通知出现的那几十秒里刚好解绑、
且通知随后消失，仍可能漏。遇到漏记时，`/autobook` 页的「诊断」块会显示断在哪一层
（监听服务 / 补抓通道 / 抓取统计），方便判断要不要再去系统里调设置。

## 五、数据与兼容

- 无数据库结构变化（仍 schema v7）；开关只是本机偏好；
- 三个包同一把签名，可直接覆盖安装 v0.8.15，数据保留；
- 覆盖安装后「我的」页角标应显示 **v0.8.16**。

## 六、装哪个包

| 你的手机 | 下哪个 |
|---|---|
| 绝大多数近几年的 Android（arm64） | **arm64-v8a** |
| 很老的 32 位机器 | armeabi-v7a |
| 模拟器 / x86 平板 | x86_64 |

校验下载完整性：对照 `SHA256SUMS.txt`；签名指纹与自证方式见 `VERIFY.md`。
